# Markanto 0.1.0 — performance baseline

Recorded at the 0.1.0 freeze as the reference point for future releases. Track
`parse` vs `marked.lexer` (both turn source into a structured tree without
rendering) — a regression is a scenario moving materially against `marked` on
the **same** runtime and machine.

Regenerate with:

```sh
bun run bench       # Node
bun run bench:bun   # Bun
```

`marked` v18.0.11 · corpus: 14 realistic docs (`test/corpus-realistic/`, ~17 KB)
+ an 814 KB synthetic plain document · measured 2026-09-04, WSL2 (Linux
6.18, x86-64). Absolute ms/op are machine-specific; the ratio and the MB/s
column are the portable signal.

## Node 24.18.0

| scenario | marked ms/op | Markanto ms/op | marked MB/s | Markanto MB/s | Markanto vs marked |
|---|--:|--:|--:|--:|--:|
| 14 realistic docs (17 KB) | 1.008 | 1.104 | 17.6 | 16.1 | 1.09× slower |
| largest realistic doc (2.0 KB) | 0.095 | 0.101 | 21.6 | 20.2 | 1.07× slower |
| 814 KB synthetic | 23.568 | 33.502 | 35.4 | 24.9 | 1.42× slower |
| 814 KB synthetic — whole pipeline¹ | 25.520 | 44.965 | 32.7 | 18.5 | _1.76× slower_ |

## Bun 1.4.0

| scenario | marked ms/op | Markanto ms/op | marked MB/s | Markanto MB/s | Markanto vs marked |
|---|--:|--:|--:|--:|--:|
| 14 realistic docs (17 KB) | 1.844 | 1.221 | 9.6 | 14.5 | 1.51× faster |
| largest realistic doc (2.0 KB) | 0.181 | 0.127 | 11.3 | 16.1 | 1.42× faster |
| 814 KB synthetic | 66.373 | 32.636 | 12.6 | 25.6 | 2.03× faster |
| 814 KB synthetic — whole pipeline¹ | 67.298 | 47.959 | 12.4 | 17.4 | _1.40× faster_ |

¹ Orientation only — Markanto emits a canonical Markanto surface, `marked` emits
HTML. Not apples-to-apples.

## Reading

- **Markanto throughput is runtime-stable** (~25 MB/s on the large document
  under both Node and Bun); `marked` is ~3× faster on Node than on Bun for the
  same work, because its regex-driven lexer leans on a V8 fast path that JSC
  does not match.
- On Node, Markanto parses in the **same order of magnitude** as `marked` — a
  little slower on the large synthetic input, within noise on small realistic
  documents.
- On Bun, Markanto's forward scanner is **1.4–2.0× faster** than `marked.lexer`.
- These are also the numbers to watch for a per-release Markanto-vs-Markanto
  regression: the MB/s column should not fall between 0.1.0 minor releases on
  the same runtime.
